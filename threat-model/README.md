# Threat Model as Code — TicketFlow

Versioned threat model for the project, built with [pytm](https://github.com/OWASP/pytm) (OWASP).

| File | Purpose |
|---|---|
| [`tm.py`](tm.py) | **Source of truth** for the system (actors, flows, trust boundaries). Discovery engine. |
| [`threats.md`](threats.md) | **Official curated registry** of threats — the **T01–T25** table (STRIDE). |
| [`report-template.md`](report-template.md) | Template for the report generated by pytm. |
| [`Makefile`](Makefile) | Regenerates the DFD, sequence diagram and report into `out/` (gitignored). |

## Getting started

```bash
# Tooling (Kali/Debian)
python3 -m venv .venv-tm && source .venv-tm/bin/activate
pip install pytm
sudo apt install graphviz default-jre plantuml

# Generate DFD + sequence + report into out/
cd threat-model
make all
```

> ℹ️ pytm is a **Python** tool: it is not part of the NuGet `packages.lock.json`
> files or `NuGet.config` — no impact on the NuGet single-source rule.

## Principle

`tm.py` and `report-template.md` produce a list of **candidate** threats. These
are **curated by hand** into `threats.md` (T01–T25), which is the registry
referenced by the code, the pull requests, the DoR/DoD and `guardian.yml`.

**Do not renumber** T12/T13/T14/T20: those IDs are already used in the
repository configuration. *The AI proposes, a server-side rule or a human decides.*
